## Protection and evidence

`ROUTEOPS_PLANNING_MAX_SNAP_DISTANCE_M` defaults to 250 m. This configurable
local threshold is above every measured replacement point (at most 25.8 m)
and the original delivery (46.1 m), while excluding the old centers by more
than 2 km. It is a local operational guard, not a claim about every road
network. The check reads the *same directional OSRM table response* used for
CD selection. It runs before allocation and therefore before inventory locks
or reservations. An excessive adjustment returns `ROUTING_SNAP_TOO_FAR`, a
point without a usable road returns `ROUTING_POINT_UNCOVERED`, and a missing
pairwise path returns `ROUTING_NO_PATH`; OSRM infrastructure failures remain
`ROUTING_DEPENDENCY_FAILED`. None is reported as missing stock.

The immutable allocation decision snapshot stores the original and snapped
coordinates, distance, business identifier, threshold, and matrix-based
choice evidence. The run exposes that evidence, including failures before
allocation. A recovered worker reads the allocation snapshot instead of
silently replacing the prior evidence. Route reconciliation checks the
geometry endpoints and every stop against the route line using the configured
250 m network tolerance, and checks delivery coordinates against the imported
order within 2 m for coordinate encoding precision. A mismatch rejects the
solver response and releases held reservations.

The map fits new route geometry and stops and reacts to container resizes. It
preserves manual camera movement during status polling, provides explicit
recenter/all-routes actions, distinguishes CD and delivery markers, and lists
coincident stops through a text-only popup. No marker is displaced to hide
coordinate discrepancies.

## Accepted limitations

- The 126-test backend result is a previously approved result; the external
  package retains smoke/demo responses but has no full textual backend test log.
- Pagination with more than 20 batches is covered by the frontend regression
  test. Browser evidence demonstrates automatic status synchronization and
  selection recovery, without a live 21-batch pagination capture.
- Browser camera evidence covers a READY status refresh without new geometry.
  A manually displaced camera during an in-flight RUNNING poll was not captured;
  the automated test covers a status change without another bounds fit.
- Responsive evidence uses the integrated browser at desktop 1440×900, tablet
  900×768, and mobile 390×844 viewport sizes; it is not a physical-device test.
- The Vite bundle remains 1,859.40 kB before gzip, with the existing nonblocking
  warning. Assignment remains deterministic and auditable without a global
  optimality claim. Routing measurements and the 250 m guard apply to the
  pinned local road network and fixtures.
